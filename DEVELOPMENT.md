# Development Guide

This guide covers the development workflow, build system, and release automation.

## Prerequisites

- Node.js 20+
- npm

## Setup

```bash
npm install
```

## Build

Generate `_dist/` artifacts locally (useful for testing):

```bash
npm run build
```

This produces `_dist/*.user.js` (full scripts) and `_dist/*.meta.js` (metadata-only for update checks). The build stamps `@version` from `package.json`, adds `@modified`, and rewrites `@updateURL` / `@downloadURL` to point at `_dist/` raw URLs.

## Versioning (Fully Automatic)

**Script versions** use a date-based format `YYYY.MMDD.HHMM` (e.g. `2026.0420.2150`):

- Each script has its own version, only bumped when that script's content changes
- The build compares source against existing `_dist/` output; unchanged scripts keep their version
- This ensures userscript managers always see a higher version after real changes

**Repo version** (`package.json`) is managed separately by [semantic-release](https://github.com/semantic-release/semantic-release) for tagging/releases — it is not used in script `@version` headers.

### Conventional Commits

Use [Conventional Commits](https://www.conventionalcommits.org/) to drive version bumps:

| Prefix                                                   | Effect                          |
| -------------------------------------------------------- | ------------------------------- |
| `fix:`                                                   | Patch bump (e.g. 3.0.0 → 3.0.1) |
| `feat:`                                                  | Minor bump (e.g. 3.0.1 → 3.1.0) |
| `feat!:` or body contains `BREAKING CHANGE:`             | Major bump (e.g. 3.1.0 → 4.0.0) |
| `chore:`, `docs:`, `style:`, `refactor:`, `test:`, `ci:` | No release                      |

## GitHub Actions

The repository has one workflow:

- **release.yml**: Runs on push to `main`. Uses semantic-release to determine the next version from conventional commits, runs the build script, commits `_dist/` and `package.json` back to `main`, creates a GitHub release, and tags the commit.

Release commits include `[skip ci]` to prevent infinite loops.

## Workflow

### Adding or Modifying Scripts

1. Edit source scripts in the appropriate category directory
2. **Never** edit files in `_dist/` — they are generated
3. Commit with a conventional commit message (e.g. `fix: correct DDG selector`)
4. Push to `main` (or merge a PR)
5. CI handles versioning, building, and releasing automatically

### Testing Locally

1. Run `npm run build` to generate `_dist/` files
2. Install the `_dist/*.user.js` file in your userscript manager
3. Test on target websites
4. Check browser console for errors
